## Database Isolation Evidence

The intended safety chain is materially better:

1. Vitest declares `DATABASE_URL=file:./test.db` before setup.
2. Setup rejects absent URLs, URLs without `test.db`, and URLs containing `dev.db`.
3. Setup runs schema initialization with an explicit test URL.
4. The normal instructor database is `prisma/dev.db`; both `dev.db` and `test.db` are ignored by Git.

This is not proof that destructive tests cannot touch the instructor database until it runs successfully. The added proof test itself reads `__dirname` in ESM without a `fileURLToPath(import.meta.url)` definition. Unlike `tests/setup.ts`, that test file defines no `__dirname`. Correct this and run the suite with an audit-created isolated database before claiming the protection is proven.

## Demo Reset Reproducibility

Demo B properly separates live coding from the main working copy using `git worktree add`. The preflight cleanup is nevertheless destructive. A path exists check is not enough to establish that `../demo-worktree` is the disposable worktree created by this guide. Do not remove it recursively or forcibly without verifying it is a registered disposable worktree, checking it is clean, and obtaining an explicit confirmation. The main-worktree `npm run db:reset` also intentionally resets the instructor data; it is safe only if this is clearly a dedicated teaching database and not active instructor work.
